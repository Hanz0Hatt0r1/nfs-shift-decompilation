# Process 3 — audio-path assessment of the retail guest frontier (2026-10-21)

## Scope and provenance

Independent **read-only** hypothesis assessment, not the ongoing display-list consumer audit. Original retail PC 1.02 x86 PE32 `SHIFT.exe`, SHA-256 `eca479aa2d8dbb88bc55709d91ae5c7159ae1b00fc9555d6701000c26de8aee1`. Evidence comprises the user's v520/v527/v659/v667/v692 observations and GitHub sources checked for this task. No local PE, raw trace, Ghidra database, audio device or native Windows retail process was examined. No source changes or PR.

**Verdict:** **No observed audio blocker on the bounded startup/host-frame path.** The v520 worker/predicate stall was later overcome by a worker write in v527, and the next reported missing export `rvi_0057da20` belongs to an allocator/FESL/online-related call chain, **not an established audio dependency**. The v667 32-import audio-inclusive probe detected no selected WinMM/MSACM import/module-load/GetProcAddress event through its 360-host-frame horizon. v692 ran to 360 host frames without blocker but **without proof of retail rendering**. The absence of observed audio calls is not a global assertion that the retail PE never uses audio or that no audio dependency exists in a later/different path.

## Method and exact evidence

1. **Pinned identity and chronological separation.** Treat v520, v527, v667 and v692 as **separate runs**, not one uninterrupted call trace. The retail PE hash is pinned; different module manifests/runtime integrations and sampling horizons can change reachability. Compare only reported events, not inferred cross-run call stacks.
2. **Scheduler frontier, v520 → v527.** v520: `KERNEL32.dll!ResumeThread` returned `1` for guest worker handle `0x00080060` in `FUN_006496f0`; predicate `FUN_006550f0` had seen `0x2` at indirect word `0x27f39c64` (bit 2 clear). The return value denotes the **previous suspend count**, not proof of scheduling. Later v527: guest worker thread ID `0x00010006` executed `0x00649b10`, wrote `0x00000006` to `0x27f39c64`, and the predicate returned true, advancing the main thread. This **removes the historical v520 false-predicate state as a persistent blocker**; it does not demonstrate audio involvement.
3. **Next export, v527.** Missing P-code export `rvi_0057da20` reached from `0x00590d60`. User-supplied retail PE semantics of `0x0057da20`: read global `0x00be6ca8`; when null call `0x0062e1a0`; then call `0x00638300` for allocation size `0x80`. The supplied `0x00590d60` / `FUN_0057e380` chain references FESL allocator, `Online_PlasmaLogEnabled`, and `Online_GameProtocolVersion`. **Classification:** allocator/online-related evidence, not an audio call or proven audio dependency. The function was later included in the module manifest (v659), so its historical missing-export failure must not be carried forward as a current audio blocker.
4. **Audio-specific bounded negative, v667.** A **32-import** probe included WinMM/MSACM API targets. Within the reported **360-host-frame** horizon: **zero** selected audio import calls, **zero** audio-related module loads, **zero** audio-related `GetProcAddress` queries and **no unimplemented PE import**. These are negative observations **within that instrumented selection and horizon**. They do not establish absence of static audio imports, an uninstrumented COM/vtable/audio callback, a different path or a later initialization.
5. **Later guest progress, v692.** Recompiled guest P-code runtime, 360 host frames, **1,738,845 dispatches**, **4,729 unique functions**, `validation_errors=0`, `blocker=null`, `guest_draw_translation=false`, `retail_rendering_proven=false`. This confirms only bounded host-loop execution, not UI, first retail render, native execution, or audio initialization.

## Does retail audio precede UI / first Draw*?

**Not established.** There is a **real static audio-related callsite surface** in the retail reverse-engineering artifacts, but no supplied **dynamic call chain** showing it executes before the first UI/display-list action or D3D9 Draw*. No observed WinMM/MSACM failure precedes the v667 bounded host-frame horizon. The v527 allocator/FESL export cannot responsibly be relabeled as audio from the supplied code.

**Confidence:** high that the reported v667 selected trace has no audio event in its bounded window; high that v527 overcame the v520 predicate; moderate that audio compatibility is **not the immediate observed blocker** for the measured path; insufficient evidence to prove audio globally unnecessary or that a future audio path is functional.

## One smallest read-only target probe

**One 360-host-frame replay** with the **same pinned PE, module manifest and runtime** as the latest reproducible guest run, retaining complete selected-event coverage and a nontruncation marker. Record **only** (i) the first call/return of `WINMM.dll!waveOutOpen`, `waveInOpen`, `timeSetEvent`, relevant MSACM calls, `DSOUND.dll` import resolution, and audio-related `LoadLibraryA/LoadLibraryW/GetProcAddress`; (ii) the **six exact static audio callsites** `0x006135ee,0x009991f6,0x00999c69,0x0061339e,0x00999714,0x009a8e7d` and callback entries `0x0099955b,0x009a8d8f` **if reached**; (iii) first guest `DrawPrimitive/DrawIndexedPrimitive/DrawPrimitiveUP/DrawIndexedPrimitiveUP` import as a comparison marker, plus actual first display-list/UI callsite **only if independently resolved**. Do not invent a UI marker address.

For each **reached** audio event capture guest thread, function/callsite, import name or module/symbol string, args/callback pointer, return/EAX, last-error if available, subsequent branch and any wait/blocker. For no event, record the **selected target inventory**, beginning/end guest dispatch, first/last host frame, event count and `trace_truncated=false`; report **not observed in this window**, not “never used.” If audio occurs **before** a blocked first-render path, only an observed return/branch/wait dependency can elevate it to a blocker. Do **not** force guest state, fabricate successful audio returns or alter runtime/renderer.

## Decision

**Current blocker classification: audio is unsupported as the immediate cause of the observed original-PE guest frontier.** The v520 worker gate has independent non-audio progress evidence, the v527 next missing export is allocator/FESL-related, and v667 does not reach the selected audio imports. **Not ruled out for future paths or for all audio APIs.** No code change, PR, or speculative audio stub is justified by these observations.
