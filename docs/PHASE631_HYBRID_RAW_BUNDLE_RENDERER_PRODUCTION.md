# Phase 631 — hybrid raw/bundle renderer production

Phase 631 joins the two existing production paths without weakening either
proof boundary:

- Phase 628 supplies exact static renderer reports from handoff bundles;
- Phase 630 regenerates capture-derived reports from the historical raw JSONL;
- Phase 627 runs the exact Phase 619→626 renderer frontier.

The new tool is:

`tools/run_silverstone_renderer_hybrid_production.py`.

## Pipeline

```text
out.zip / report bundles
→ Phase 628 embedded-format + canonical-payload index
→ exact base renderer requirement audit
→ exact Phase 618 ambiguity audit

historical shift_d3d9_capture.jsonl
+ SHIFT.PEImageEvidence/1
+ exact runtime shader target set
→ Phase 630
→ regenerated draw-local evidence
→ regenerated IMB runtime capture pipeline

static reports + regenerated capture reports + corpus
→ Phase 627
→ Phase 619 / 620 / 622 / 623 / 624 / 625 / 626
```

This stage still never launches the original game and requires no new capture.

## Source authority

The source authority is intentionally split by evidence type.

### Static/frontier handoff reports

These remain Phase 628 bundle identities:

- `SHIFT.D3D9RendererRequirementAudit/1`;
- `SHIFT.IMBDrawLocalAmbiguityAudit/1`.

Both must be exact and unambiguous. Missing or multiple distinct canonical
payloads stop the hybrid run before raw-capture processing.

### Capture-derived reports

These are regenerated by Phase 630 and are never taken from the bundle as the
production input:

- `SHIFT.D3D9TargetDrawLocalEvidence/1`;
- `SHIFT.IMBRuntimeCapturePipeline/1`.

Bundle occurrences of those formats are cross-check evidence only.

## Canonical cross-check

All cross-checks use the same canonical JSON identity convention as Phase 628:

```text
UTF-8 JSON
+ sorted object keys
+ compact separators
→ SHA-256
```

Possible statuses are:

- `bundle-copy-absent-regenerated-source-used` — no derivative copy exists in
  the bundle; the raw regeneration is used directly;
- `exact-canonical-match` — one bundle content identity equals the regenerated
  report exactly;
- `exact-canonical-match-among-bundle-variants` — multiple derivative bundle
  variants exist, but the raw regeneration exactly equals one of them;
- `bundle-regenerated-canonical-mismatch` — none of the bundle identities equals
  the regenerated report; production stops.

The third case is not ranking. The raw evidence deterministically reproduces one
content identity byte-for-byte at the canonical JSON level. Filename, archive
order, timestamps and occurrence counts are not considered.

## Why a mismatch blocks

The Phase 618 ambiguity handoff was derived from a capture-local/static join.
If the current raw-capture tooling reproduces a different draw-local contract
than every derivative copy in the handoff archive, silently combining those
artifacts would make their provenance relationship unclear.

Therefore a mismatch is an offline provenance blocker. It is **not** interpreted
as evidence that the historical capture is wrong, and it does not request a new
capture.

## Runtime shader targets

Shader-target selection uses this order:

1. explicit `--runtime-shader-targets`, when supplied;
2. one exact Phase 628 bundle target-set report;
3. committed `evidence/silverstone_era3_runtime_shader_targets.json`.

If the bundle contains target-set occurrences, the chosen target set must match
one of their canonical content identities exactly. Otherwise the run blocks.

This prevents an unrelated committed/default target inventory from silently
replacing a different handoff target set.

## Object candidate join

`SHIFT.SGBRuntimeObjectCandidateJoin/1` is optional before Phase 624 proves that
repeated scene placements survive.

- one exact bundle report is passed to Phase 627;
- ambiguous bundle variants are never ranked or selected;
- in the ambiguous case Phase 627 receives no object-candidate report;
- Phase 627/625 then decides whether that missing exact report is actually a
  blocker for the observed draw set.

Thus optional ambiguity does not prematurely stop production, but it cannot be
promoted into an instance identity.

## Usage

```bash
python tools/run_silverstone_renderer_hybrid_production.py \
  out.zip \
  --capture-jsonl shift_d3d9_capture.jsonl \
  --pe-evidence out/shift_pe_image_evidence.json \
  --output-dir out/silverstone_renderer_hybrid \
  --corpus Silverstone_Era3_.zip \
  --corpus SHIFT_tail.zip
```

An explicit exact shader-target inventory may be supplied with:

```bash
--runtime-shader-targets evidence/silverstone_era3_runtime_shader_targets.json
```

## Output

```text
bundle/
  silverstone_renderer_report_bundle_index.json
  <exact normalized bundle reports>
raw/
  d3d9_usage_map.json
  d3d9_target_draw_local_evidence.json
  silverstone_imb_runtime_capture_pipeline.json
  silverstone_renderer_raw_capture_bootstrap.json
production/
  silverstone_renderer_production_run.json
  <Phase 619-626 reports>
silverstone_renderer_hybrid_production_run.json
```

The top-level format is:

`SHIFT.SilverstoneRendererHybridProductionRun/1`.

It records bundle blockers split into fatal and tolerated derivative/optional
report blockers, shader-target provenance, raw-bootstrap state, canonical
cross-checks, optional object-candidate state, the final renderer frontier and
all remaining blockers.

## Fail-closed boundaries

Phase 631 records explicitly that:

- bundle capture-derived reports are not selection authority;
- only exact raw canonical equality can identify one derivative bundle variant;
- a capture-derived mismatch blocks production;
- static base/ambiguity report ambiguity always blocks;
- object-candidate ambiguity is never ranked;
- ranking/frequency is never proof;
- a missing historical capture event does not imply recapture;
- `buffer_payload` remains a last conditional fallback;
- the original game is never executed.

## Regression coverage

`tests/test_run_silverstone_renderer_hybrid_production.py` covers:

- bundles containing only the static required reports;
- exact derivative bundle cross-checks while production still uses regenerated
  reports;
- mismatch blocking before Phase 627;
- exact raw equality disambiguating multiple derivative handoff variants;
- ambiguous static base reports blocking before raw bootstrap;
- ambiguous object-candidate reports remaining unselected until downstream need
  is proven;
- chosen runtime shader targets being required to match any bundle target-set
  identity exactly.
