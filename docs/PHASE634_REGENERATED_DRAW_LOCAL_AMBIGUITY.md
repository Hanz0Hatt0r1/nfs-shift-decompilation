# Phase 634 — regenerated draw-local ambiguity

Phase 634 removes `SHIFT.IMBDrawLocalAmbiguityAudit/1` from the set of renderer
reports that must be prepared manually before Silverstone production.

The new entry point is:

```text
tools/run_silverstone_renderer_ambiguity_regeneration.py
```

It never launches the original game. It replays the existing source-backed and
capture-backed builders against the historical D3D9 JSONL and the original
BFF/ZIP corpus.

## Input boundary

The runner consumes:

- historical raw D3D9 JSONL;
- exact `SHIFT.IMBRuntimeShaderTargetSet/1`;
- exact `SHIFT.D3D9TargetDrawLocalEvidence/1` regenerated by Phase 630;
- one or more source BFF/ZIP corpus paths.

It does **not** consume an existing Phase 618 report as proof input.

## Replayed evidence graph

The orchestration is:

```text
historical raw D3D9 JSONL
  + exact runtime shader targets
        |
        +--> Phase 603 target draw signature catalog
        |      `SHIFT.D3D9TargetDrawSignatureCatalog/1`
        |
        +--> Phase 613 pointer observations
               `SHIFT.D3D9TargetPointerObservations/1`

BFF/ZIP corpus
  +--> IMB corpus audit
       `SHIFT.IMBCorpusAudit/1`

Phase 603 + shader targets
  -> Phase 606 runtime pipeline candidates
     `SHIFT.IMBRuntimePipelineCandidateJoin/1`

Phase 603 + Phase 606 + corpus audit
  -> Phase 610 geometry-shape candidates
     `SHIFT.IMBRuntimeGeometryShapeCandidateJoin/1`

Phase 603 + Phase 610 + BMT/DDS/FX/FXO corpus evidence
  -> Phase 611 material-descriptor candidates
     `SHIFT.IMBRuntimeMaterialDescriptorCandidateJoin/1`

Phase 613 + Phase 611
  -> Phase 615 geometry-pointer candidates
     `SHIFT.IMBRuntimeGeometryPointerCandidateJoin/1`

Phase 630 draw-local + Phase 615
  -> Phase 617 draw-local static candidates
     `SHIFT.IMBDrawLocalStaticCandidateJoin/1`

Phase 617
  -> Phase 618 ambiguity audit
     `SHIFT.IMBDrawLocalAmbiguityAudit/1`
```

Every intermediate report is persisted. The Phase 634 manifest format is:

```text
SHIFT.SilverstoneRendererAmbiguityRegeneration/1
```

This allows old handoff reports to be compared later by canonical JSON identity
without making those handoffs selection authorities.

## Multi-corpus FX policy

Phase 611 historically had a convenient single-`render.bff` path for FX source
lookup. A direct production runner cannot assume one archive is authoritative,
because the current offline input is a corpus of BFF/ZIP files.

Phase 634 therefore scans `.fx` entries across every materialized BFF and groups
them by normalized resource path.

A duplicated path is accepted only when every occurrence is byte-identical.
Equivalent duplicates collapse to one source. If the same normalized `.fx`
path has two different SHA-256 payloads, Phase 611 is blocked with:

```text
conflicting-fx-source-paths:<path>...
```

No archive order, occurrence count, frequency, or filename preference selects a
winner.

FXO pixel reflection already has its own conservative behavior: divergent CTAB
sampler signatures for one exact pixel-shader byte SHA remain ambiguous.

## Proof semantics preserved

Phase 634 does not weaken any existing stage:

- runtime pipeline matches remain candidate evidence;
- geometry descriptor matches remain candidate evidence;
- BMT/DDS texture descriptor agreement is not texture identity;
- capture-local buffer pointer/generation identity is not portable resource
  identity;
- a Phase 617 single static candidate is not render admission;
- ranking and frequency are not proof;
- any missing upstream report blocks only dependent stages;
- conflicting static evidence is retained or fails closed, never silently
  selected.

The final Phase 618 classification semantics are unchanged.

## Capture boundary

No new capture is requested by this phase.

The historical capture already contains the observations needed by this graph:
shader creation/bind history, draw ranges, declarations, buffer descriptors and
generations, texture descriptors, and target draw state. Observations known to
be absent from the historical capture (`SetSamplerState`, buffer payload,
portable path+SHA and texture snapshots) are not inputs to the Phase 603→618
regeneration graph.

Therefore:

```text
original game execution required: no
new capture required: no
```

## Production consequence

After Phase 634, the direct renderer bootstrap no longer needs a manually
prepared Phase 618 ambiguity JSON. The next integration step is to let the
Phase 631/633 hybrid production path regenerate Phase 618 after Phase 630 raw
bootstrap, compare any bundle Phase 618 copy only as an exact canonical
cross-check, and then regenerate the Phase 633 base audit from that result.
