# Phase 556 — source-backed IMB binary mesh schema

Phase 556 follows the Phase 555 `.imb` binary loader
`FUN_00859800` into the serialized mesh payload.

The variable version/name prefix is still deliberately unresolved. The decoder
therefore requires the caller to supply the fixed mesh-header offset explicitly.
Everything after that boundary is decoded only where the retail loader gives a
direct source consumer.

## Common fixed header

After the variable prefix and NUL-terminated embedded resource name,
`FUN_00859800` reaches an aligned fixed header.

| Source offset | Field | Runtime destination |
|---:|---|---:|
| `+0x00` | vertex count | MeshType `+0x18` |
| `+0x04` | stream count | declaration construction |
| `+0x08` | primitive count | MeshType `+0x28` |
| `+0x0c..+0x18` | bounding sphere XYZ + radius | `+0x30..+0x3c` |
| `+0x1c..+0x24` | AABB min XYZ | `+0x40..+0x48` |
| `+0x28..+0x30` | AABB max XYZ | `+0x50..+0x58` |

Runtime W components at `+0x4c/+0x5c` are set to `1.0` by the loader.

## Optional bone block

A source version/feature gate controls the next two dwords.

When present:

- `+0x34`: bone count;
- `+0x38`: matrix-block offset relative to source `+0x3c`;
- `+0x3c`: start of the NUL-terminated bone-name block.

The matrix block contains `bone_count` records of `0x30` bytes. Each record
is 12 floats arranged as four XYZ rows. The runtime expands each record to a
`0x40` 4x4 by inserting W values `0,0,0,1`, then builds the second matrix
array through `FUN_006308b0`.

Runtime fields:

- `+0x60`: bone count;
- `+0x64`: bone-name/identifier array;
- `+0x68`: expanded `0x40` matrices;
- `+0x6c`: matrices generated by `FUN_006308b0`.

## Stream descriptors

Immediately after the optional bone matrices, the loader reads
`stream_count` records at `0x0c` stride:

```text
u32 Type ordinal
u32 Usage ordinal
u32 Channel
```

The exact consumers are the already recovered renderer functions:

- `FUN_00853c20(Type)`;
- `FUN_00853c40(Usage)`;
- Channel copied into the runtime declaration record.

This joins the IMB binary loader directly to the existing D3D9 Type/Usage
evidence instead of defining a second semantic table.

The runtime declaration record has `0x08` stride and the loader repacks the
source attribute streams into one interleaved runtime vertex buffer.

## Primitive runtime records

The loader allocates one `0x50` runtime record per fixed-header primitive.

Observed runtime fields include:

- sphere at `+0x00..+0x0c`;
- AABB min/max at `+0x10..+0x2c`;
- primitive type `+0x30 = 4`;
- material handle `+0x34`;
- primitive count `+0x38`;
- derived index count `+0x3c`;
- index buffer `+0x40`;
- optional bone palette count/pointer `+0x44/+0x48`;
- two 16-bit vertex-range values at `+0x4c/+0x4e`.

The source primitive section begins only after variable-size vertex payload
consumption, so Phase 556 records this runtime schema but does not claim a
complete primitive-source parser yet.

## Decoder

`src/formats/imb_format.py` emits
`SHIFT.IMBBinaryMeshSchema/1`.

Example:

```bash
python shift_importer.py imb-binary-schema \
  extracted_mesh.imb out/imb-schema.json \
  --header-offset 0x40 \
  --has-bone-block
```

The header offset and bone-block gate are explicit evidence inputs. They are
not guessed.

## Closed in this phase

- fixed IMB mesh header field mapping;
- optional bone-name/matrix block;
- 12-float source matrix → 4x4 runtime expansion;
- Type/Usage/Channel stream descriptor table;
- exact vertex-payload start after the decoded tables;
- runtime primitive-array stride and known fields;
- partial decoder exposed through the root CLI.

## Remaining boundary

Still open:

- automatic parsing of the variable IMB version/name prefix;
- exact byte consumption for every vertex Type/version variant;
- full primitive-source parsing;
- conversion into neutral MEB-like geometry without asserting container
  equivalence;
- IMX XML neutral adapter.

`evidence/imb_binary_mesh_schema_source.json`.
