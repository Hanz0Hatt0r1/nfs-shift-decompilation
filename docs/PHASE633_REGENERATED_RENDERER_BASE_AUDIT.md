# Phase 633 — regenerated renderer base audit

Phase 633 removes `SHIFT.D3D9RendererRequirementAudit/1` from the set of renderer
reports that must be prepared manually before Silverstone production.

The report is derivable from evidence that is already present:

```text
historical raw D3D9 JSONL
→ exact shader create/bind/use history
→ exact texture create/SetTexture history
→ explicit sampler-state observation history
→ draw-local evidence
+ exact Phase 618 ambiguity report
→ renderer requirement audit
```

No new capture is required and the original game is never launched.

## Tool

`tools/run_silverstone_renderer_base_audit_regeneration.py` consumes:

- the existing historical raw D3D9 JSONL;
- `SHIFT.IMBRuntimeShaderTargetSet/1`;
- `SHIFT.D3D9TargetDrawLocalEvidence/1` regenerated by Phase 630;
- the exact `SHIFT.IMBDrawLocalAmbiguityAudit/1` report.

It emits:

```text
d3d9_shader_use_evidence.json
  SHIFT.D3D9ShaderUseEvidence/1

d3d9_target_texture_sampler_evidence.json
  SHIFT.D3D9TargetTextureSamplerEvidence/1

d3d9_renderer_requirement_audit.json
  SHIFT.D3D9RendererRequirementAudit/1

silverstone_renderer_base_audit_regeneration.json
  SHIFT.SilverstoneRendererBaseAuditRegeneration/1
```

The shader-use and texture/sampler reports are rebuilt from the same historical
capture path recorded by SHA-256 in the regeneration manifest.

## Capture-request boundary

The base-audit builder supports explicit hard capture requirements, but Phase
633 deliberately supplies **none**:

```text
hard_requirements = ()
```

Therefore capture observations that are genuinely absent from the historical
capture remain useful negative evidence, not recapture requests.

For the current historical capture this includes the previously established
observation gaps:

- explicit `SetSamplerState` history;
- portable `resource_path + resource_sha256` identity;
- captured texture snapshots;
- VB/IB `buffer_payload` events.

They remain listed under `genuinely_absent_capture_observations`, while:

```text
capture_required_now = false
capture_blockers = []
```

unless some future downstream phase explicitly proves one of those observations
is a hard requirement.

## Hybrid production integration

`tools/run_silverstone_renderer_hybrid_production.py` now accepts:

```text
--regenerate-base-audit
```

The default Phase 631 behavior is unchanged. Without the flag, an exact
bundle-selected base audit is still required.

With the flag, the policy becomes:

```text
bundle
→ exact Phase 618 ambiguity report

raw JSONL
→ Phase 630 draw-local/capture pipeline
→ Phase 633 shader-use + texture/sampler evidence
→ regenerated base audit

regenerated base audit
↔ optional bundle base-audit canonical SHA cross-check
→ Phase 627 production
```

A bundle base audit is no longer a selection authority in this mode.

If the bundle has no base-audit copy, the regenerated report is used.

If the bundle has one canonical identity, it must equal the regenerated report.
A mismatch blocks production.

If the bundle contains several distinct historical base-audit payloads, the
bundle ambiguity is tolerated only when the regenerated report exactly matches
one canonical identity. This is byte-content disambiguation, not ranking.

## Direct PE-image production

The Phase 632 entry point:

`tools/run_silverstone_renderer_pe_image_hybrid_production.py`

now enables Phase 633 automatically.

Its direct path is therefore:

```text
static PE image bytes
→ PE evidence
→ exact Usage map

historical raw D3D9 JSONL
→ draw-local evidence
→ runtime capture pipeline
→ shader-use evidence
→ texture/sampler evidence

exact Phase 618 ambiguity
+ regenerated raw evidence
→ regenerated renderer base audit

bundle base-audit copy, when present
→ canonical cross-check only

→ Phase 627
→ Phase 619/620/622/623/624/625/626
```

The PE image is still read only as static data and is never executed.

## Remaining manual static handoff

After Phase 633, the required bundle evidence for the direct renderer production
path is reduced further.

The important remaining required static handoff is the Phase 618 ambiguity
report, which itself is derived from:

```text
Phase 630 draw-local evidence
+ Phase 615 runtime geometry-pointer candidate join
→ Phase 617 static candidate join
→ Phase 618 ambiguity audit
```

The next offline target is therefore to reconstruct that Phase 615→617→618
chain from the available corpus and existing static reports, rather than asking
for new runtime capture data.

## Regression policy

Tests verify that:

- historical sampler/path/snapshot/buffer gaps do not become hard capture
  requirements;
- a missing bundle base audit is accepted only in regenerated mode;
- a mismatching bundle base audit blocks production;
- multiple bundle variants can be disambiguated only by exact canonical match
  with the regenerated report;
- default Phase 631 behavior remains backward-compatible.
